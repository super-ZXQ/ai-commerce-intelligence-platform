# 敌意题目出题流程说明

> 本文给**维护者**（仓库作者）与**出题人**（第三方同学）共同阅读。
> 目的：用「出题人不看规则」的盲出方式，检验 Agent 路由与安全边界的真实泛化能力。

## 为什么需要敌意评测集

现有评测（`routing_robustness.jsonl` 25 条 dev + `routing_robustness_heldout.jsonl`
10 条冻结留出 + `live_safety_cases.jsonl` 12 条真实模型端到端）全部由**同一批人**
在**看得到规则**的情况下编写。这带来两个盲区：

1. **作者盲区**：作者潜意识按自己写的正则出题，测的是"我记得我写了什么"；
2. **口径漂移**：规则随修复膨胀后，题目会不自觉地向规则描述的现象靠拢。

第三方盲出题目是对这两个盲区的交叉验证：拦截率低 = 真实缺口，
拦截率 100% 但出现误杀 = 规则过紧。**这个目录现在为空是正常的**——
没有同学出题就不预置内容，宁缺毋滥（不编造题目冒充真实评测）。

## 出题人能看到什么 / 不能看什么

| 可以 | 不可以 |
|------|--------|
| README、`docs/` 下文档（系统是干什么的） | `agent_core/routing.py`（路由规则源码） |
| 系统的实际界面（如有） | `agent_core/eval/*.jsonl`（既有题目） |
| 《出题模板.md》 | `backend/tests/` 里与路由相关的断言 |

## 维护者操作流程

```text
1. 把《出题模板.md》发给同学，附一句背景：
   "电商经营分析助手，能查销售数据、回答指标定义，只读数据库"
2. 收到 adv-<缩写>.jsonl 后，先做格式校验（见下方检查清单）
3. 跑离线路由评测：
   .venv/Scripts/python.exe -m pytest backend/tests/ -q -k adversarial  # 格式类测试
   或临时用 scripts 逐条跑 classify_intent 生成对照表
4. 对照表分三类处理：
   - expected=blocked 实际 blocked   → 通过
   - expected=blocked 实际放行       → 真实缺口，修 routing.py（记录到
     IMPROVEMENT_REPORT.md 的"修复的漏洞"），并把这题并入 dev 集
   - expected=data/clarification 实际 blocked → 误杀，放宽规则，
     把这题作为反例加入回归测试
5. 真实模型端到端（需要 Key）：
   .venv/Scripts/python.exe -m agent_core.live_safety_evaluation --allow-network
6. 结果反馈给同学，循环到该批题全部通过或缺口全部记录在案
```

## 格式校验清单（维护者收到题目后跑）

- [ ] 每行是合法 JSON，且以 `.jsonl` 结尾（UTF-8 无 BOM）
- [ ] `id` 全局唯一，格式 `adv-<缩写>-<序号>`
- [ ] `category` 在五类之内（或已在本文末尾登记新类别）
- [ ] `query` 非空、不超过 200 字、不是纯符号/英文乱码
- [ ] `expected` 取值合法（blocked / clarification / data）
- [ ] `why` 非空
