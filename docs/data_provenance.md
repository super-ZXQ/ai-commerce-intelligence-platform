# 数据集出处与合规说明（data provenance）

> 本文档说明 `data/` 目录下三个数据文件的来源、字段结构、脱敏状态与可公开理由。
> 数据来源与清洗流程以本文档为准。

## 一、文件清单与角色

| 文件 | 大小 | 行数 | 角色 |
|------|------|------|------|
| `data/datas.xlsx` | 约 7.9 MB | 104,557 | 原始数据（未清洗，11 个字段） |
| `data/cleaned_orders.csv` | 约 16.7 MB | 102,287 | 清洗后的分析主数据（16 个字段） |
| `data/cleaned_orders.parquet` | 约 6.5 MB | 102,287 | 同 CSV 内容的列式存储版本（加载提速用） |

## 二、原始出处

- **来源**：网上公开的淘宝电商订单数据集（据项目作者口述：2024 年从公开渠道下载的淘宝订单数据；**原始下载页面未留存，无法给出精确链接**，本文档不做编造）。
- **数据时间范围（客观事实）**：订单 `下单时间` 覆盖 **2025-01-01 00:09 至 2025-12-31 23:48**（全年）。该时间以数据本身为准，与获取时间分属两个概念。
- **字段结构**：与中文电商分析领域公开流传的订单类练手数据集字段结构一致（订单/用户/商品/渠道/平台/时间/退款）。
- **使用性质**：仅用于学习与技术研究演示，不用于任何商业用途。

## 四、脱敏与隐私声明

1. **用户名已脱敏**：全量用户标识均为 `user-<数字>` 格式，**不含真实姓名、手机号、收货地址等任何直接标识信息**。脱敏在原始数据集中即为该状态（非本项目二次处理）。
2. **PII 扫描（2026-10-13 实测，全量两份文件）**：
   - `datas.xlsx` 104,557 行、`cleaned_orders.csv` 102,287 行中，用户名不符合 `user-\d+` 格式的记录数均为 **0**；
   - 对所有文本列按中国大陆手机号（`1[3-9]\d{9}`）与身份证号（`\d{17}[\dXx]`）正则扫描，**命中数均为 0**。
3. 数据中不含自由文本字段（无评论、无地址、无姓名列），不存在间接重识别所需的辅助信息。

复现扫描命令：

```powershell
.venv\Scripts\python.exe -c "
import pandas as pd
df = pd.read_csv('data/cleaned_orders.csv')
u = df['用户名'].astype(str)
print('非 user-XXX 格式:', (~u.str.match(r'^user-\d+$')).sum())   # 预期 0
print('手机号命中:', u.str.contains(r'1[3-9]\d{9}').sum())        # 预期 0
"
```

## 五、清洗流程（104,557 → 102,287 行）

完整过程见 `notebook/01_data_cleaning.ipynb`，步骤：

1. 删除订单号为空的记录；
2. 订单号去重（保留首条）；
3. 金额列转数值，删除「付款金额 > 订单金额」的异常记录及金额 ≤ 0 的记录；
4. 时间列转标准格式，删除转换失败及「付款时间早于下单时间」的记录；
5. 新增 5 个派生字段（见上表），输出 `cleaned_orders.csv`。

## 六、可公开在仓库的理由

1. **无个人信息**：用户标识为脱敏编号，全量 PII 扫描零命中（见第四节）；
2. **公开来源**：数据本身来自网上公开渠道，非任何机构的内部或生产数据；
3. **用途正当**：仅用于学习与技术演示；
4. **可复现**：清洗逻辑完整保留在 notebook 中，任何人都可用原始文件复现派生文件。

## 七、数据来源常见问题

- **"数据是真的吗？"** —— 真实下载的公开电商订单数据，10 万+ 行规模；字段结构与中文电商订单分析场景一致。
- **"有没有隐私风险？"** —— 用户列全量为脱敏编号，无姓名/电话/地址列，做过全量正则扫描并留档（本文档第四节），扫描命令可复现。
- **"为什么 xlsx 和 csv 行数不一样？"** —— xlsx 是原始数据，csv 是清洗后（去空、去重、剔除金额与时间异常）的分析数据，差异 2,270 行，清洗规则见第五节。
